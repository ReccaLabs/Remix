- PayHere formulas: verified vs assumed
  - Verified on https://support.payhere.lk/api-&-mobile-sdk/checkout-api (fetched 2026-10-10): checkout `hash = UPPER(MD5(merchant_id + order_id + amount + currency + UPPER(MD5(secret))))`; notify `md5sig = UPPER(MD5(merchant_id + order_id + payhere_amount + payhere_currency + status_code + UPPER(MD5(secret))))`; status codes 2 success, 0 pending, -1 canceled, -2 failed, -3 chargedback; action URLs `https://sandbox.payhere.lk/pay/checkout` and `https://www.payhere.lk/pay/checkout`; notify fields (incl. masked `card_no`, `card_holder_name`); required checkout fields incl. `email`, `address`, `city`, `country`, `items`; notify cannot reach localhost. Test vectors computed independently with Python `hashlib` (the documented sample hash and a notify vector).
  - Assumed (not stated by PayHere): amount format two decimals without separators (taken from their code samples); notify is sent once per status change and may be repeated (we are idempotent either way); a student without an email gets an empty `email` field — PayHere lists it as required, so the checkout page may ask for it or refuse (see TODO); address/city are sent as "Not applicable (tuition fees)" (or the receipt address) since there is no delivery.
- Deviations from plan/ADRs:
  - ADR 0008 §6 says store raw notifies in `provider_events` and process in the `payments` queue, with idempotency key `payhere:<payment_id>`. Implemented instead (as the track prompt asked): synchronous processing in one short transaction under the ledger + row locks, idempotency key `payhere:<orderId>` (one payment per order ever, whatever payment ids PayHere sends), and each verified notify recorded as an audit row (ids, status, amount — never the raw body). No `provider_events` table.
  - Valid-signature notifies with an unknown order or a merchant/amount/currency mismatch are answered 200 (and audited) rather than rejected, so PayHere does not retry something that will never match.
  - Expiry is lazy: a pending order reads as `expired` (and is stored so) when polled after 30 min; there is no sweeper job.
  - Test-payment rows live in `payhere_checkouts` with `kind = 'test'`, no student and no ledger payment.
