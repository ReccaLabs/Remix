# 0009 — File storage: private buckets, presigned uploads, processing, retention

- **Status:** Accepted · 2026-10-04
- **Settles:** [roadmap §6](../plan/05-roadmap.md#6-decision-backlog-adrs) item 0009; the `StorageProvider` row of [03-architecture](../plan/03-architecture.md); FEE-05 slip uploads now, tutes/receipts/logos later.

## Decision

- **Provider:** `StorageProvider` interface (already in `apps/api/src/integrations/storage`). Production: Cloudflare R2. Development/CI: the S3-compatible SeaweedFS in `infra/docker/compose.yaml`. One private bucket per environment; nothing is public.
- **Keys:** `<tenantId>/<kind>/<yyyy>/<mm>/<uuidv7>.<ext>`, generated by the server only. A key outside the caller's tenant prefix is rejected before any provider call.
- **Uploads:** the API issues a presigned **PUT** (≤ 10 min) with `content-type` and `content-length` conditions (slips: ≤ 5 MB, `image/jpeg`, `image/png`, `image/heic`, `image/heif`). The client then calls a "submit" endpoint with the key. Upload records are `pending` until a worker has processed them; unprocessed uploads are deleted after 24 h.
- **Processing (worker, `media` queue):** sniff magic bytes (never trust the extension or the declared type), re-encode images to JPEG (HEIC → JPEG), strip EXIF/GPS, cap dimensions at 2,560 px, store the processed object, and delete the original. A file that fails sniffing is rejected and the slip marked `rejected` with reason "Unreadable file". Malware scanning (ClamAV) joins in R2 for documents; slips are re-encoded images, so the re-encode is the sanitiser.
- **Downloads:** signed GET URLs valid ≤ 10 minutes, issued only after the API's permission check, with `content-disposition` set by the server. URLs are never stored or logged.
- **Retention:** slips are kept 7 years with the payment record (accounting), deleted with the tenant on account closure per the data-retention policy.
